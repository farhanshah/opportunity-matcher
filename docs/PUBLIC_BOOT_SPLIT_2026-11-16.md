## Measurements (not promises)

Latest user screenshots after PR #12: mobile **48/100**, desktop **56/100**; both remained 100 for Accessibility, Best Practices and SEO. Previous single-run scores were 70/53. Single Lighthouse scores vary.

Independent 10-page OpenSEO Lighthouse audit `5b0598f7-86a8-432f-b3ed-26127c22a804`:

- Mobile: 8.4 s JavaScript boot-up, 13.7 s main-thread work, 8.5 s script evaluation, ~620 ms estimated render-blocking CSS savings.
- Unused third-party JavaScript: Neon Auth SDK and Google AdSense. Do not remove AdSense verification or pretend third-party caching is under our control.
- This is a first-page lab audit, not CrUX field-user evidence.

## Proposed change in PR #13

For non-OAuth public homepage visits, retain marketing HTML, official-source links, verified opening cards, carousel, and lightweight live counters immediately. Defer all 111 workspace/account modules until a Passport or Sign in click, approach to the featured catalogue, or after load settles. Auth/callback and direct private-route startup remain immediate. Add a visible Sign in control that opens Neon after session restoration and ensure the account gate never exposes guest tracker state. PageSpeed and local browser tests must pass before merging.

### Caveats
- Logged-in header may take several seconds to change from Sign in to account status on landing because cloud session restoration follows the lazy workspace load.
- The historical programme-card section is still generated by the full workspace module, but observing that section starts initialization before it is reached.
- Retest authenticated sign-in, logout, password recovery, mobile menu, dark/light mode, saved/tracker, dashboard, page indexability and verified openings with real browser access.
- Repeated mobile and desktop PageSpeed runs are required after any production merge. No numerical performance improvement is guaranteed.
